# План: Discord, WhatsApp, Instagram в Fixer

Составлен по разбору Flowseal/zapret-discord-youtube, RixyPow/netzapret, RixyPow/Zapret-UNIVERSAL-preset, Asterlike/zapret2UI и кода Fixer. Всё про блокировки у конкретного провайдера не проверено, это гипотезы до этапа 0.

## Главное

- Все четыре репозитория это Windows (WinDivert, winws/winws2). Их главные приёмы (seqovl, fooling ts/badseq/md5, syndata, fake с autottl) требуют сырых пакетов и на Android без root недоступны. Переносятся **идеи и списки доменов**, а не строки аргументов.
- Что реально есть в byedpi без root: `--split`, `--disorder`, `--tlsrec`, `--fake` + `--ttl`, `--md5sig`, `--oob`, группы `-H список` и `--auto`.
- Что можно взять как есть: списки доменов (netzapret `config/lists`, Flowseal `list-general`/`list-google`), структуру «группа = список + свои аргументы», идею автоподбора.

## Что получится по сервисам

| Сервис | TCP (чат, веб, API) | UDP (голос, звонки) | Вердикт |
|---|---|---|---|
| Discord | byedpi, отдельная группа | голос по голым IP, фейки недоступны; пробуем напрямую | веб и чат скорее да, голос под вопросом |
| Instagram, Facebook | byedpi, группа Meta; QUIC сбрасываем | не нужен | да, если блок по SNI; если по IP, нет |
| WhatsApp | авторы всех репозиториев десинк не применяют (pass или туннель); свои IP, порт 5222 | звонки STUN/SRTP | десинком, скорее всего, не лечится, нужен отдельный путь |

## Этапы

**0. Диагностика на телефоне (до любого кода).** Для каждого сервиса понять тип блока: сброс по SNI, зависание после 16 КБ, блок по IP. Расширить встроенный тестер: проверочные хосты Discord (`discord.com`, `gateway.discord.gg`, `cdn.discordapp.com`, `challenges.cloudflare.com`), Instagram (`instagram.com`, `cdninstagram.com`), WhatsApp (порт 5222 к `g.whatsapp.net`). Отдельно мобильный интернет и Wi-Fi.

**1. Приложения.** Вынести `APPS` в настройки (пункт ROADMAP v1.3), добавить `com.discord`, `com.whatsapp`, `com.instagram.android`, `com.facebook.katana`. Российские приложения оставить вне VPN (allowed-режим это уже даёт).

**2. Группы byedpi и списки.** Положить списки в assets: `discord.txt`, `meta.txt` (instagram, facebook, fbcdn, cdninstagram), `youtube.txt`. Группа Roblox остаётся первой (без десинхронизации). Каждая группа получает свои аргументы через `-H`. Один процесс, один порт 21080.

**3. Подбор стратегий.** На телефоне перебрать кандидатов (`--split 1+s`, `--tlsrec 1+s`, `--disorder 1`, `--fake -1 --ttl N`, `--md5sig`) отдельно для Discord и Meta. Критерий: полный HTTPS-запрос ценнее голого handshake. Результат зашить в `DPI_ARGS`.

**4. UDP.** Оставить сброс QUIC (клиенты уходят на TCP). Для голоса Discord и звонков WhatsApp проверить прямой relay на реальном звонке. Если не работает, пробовать `--udp-fake` через SOCKS5 UDP ASSOCIATE (на Roblox там была ошибка 279, поэтому только опционально и только для этих сервисов).

**5. WhatsApp отдельно.** Если этап 0 покажет блок по IP, десинк не поможет. Варианты: схема как у Telegram (свой домен и Worker), либо встроенная прокси-настройка WhatsApp. Исследовать после этапов 1-4.

**6. Одна кнопка и нагрузка.**
- Технически можно: все пакеты в одной TUN-сессии, один byedpi с группами.
- Риски: общий читающий поток (DNS, UDP и TCP в одном цикле), поток на каждый UDP-flow (лимит 512), нагрузка на CPU и батарею от видео, MTU 1500 (проверить 1400 на LTE), IPv6 выключен.
- Меры: профили «Игры», «Соцсети», «Всё»; счётчик потоков; foregroundServiceType для Android 14+; тест длительной работы.
- Российские приложения сканируют VPN и localhost-порты: оставить их вне VPN и не открывать лишних слушателей.

**7. Автоподбор (после стабилизации).** Симптом (сброс, зависание на 16 КБ) → следующая стратегия → живая проверка → запись для домена и сети.

**8. Релиз 1.3.** Тесты на `PacketUtils`/группы, обновить README, TROUBLESHOOTING, THIRD_PARTY_NOTICES (списки netzapret под MIT, указать источник), CHANGELOG.
